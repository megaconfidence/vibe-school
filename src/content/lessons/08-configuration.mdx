Almost everything about Vibe Code is a setting: the default agent, the model, the theme, which tools are allowed, which MCP servers to load. All of it lives in one TOML file, `config.toml`, shared by the CLI and the VS Code extension. In this lesson you'll get the course project, find the settings files, learn how they stack up, and change one setting for yourself and one for the project.

## In your project

From this lesson on, the Code lessons build one project step by step: `vibe-todo`, a tiny Python todo CLI. Vibe downloads the starter for you, and this lesson adds its first Vibe file:

```text
~/vibe-school/vibe-todo/       # you choose the location
├── .vibe/
│   └── config.toml            # new: default_agent = "accept-edits"
├── todo/                      # the app: cli.py, store.py
├── tests/                     # unittest suite
├── README.md
└── .gitignore
```

Vibe also runs `git init` and commits the starter, so later lessons can show diffs, branches, and merges. Then you continue the course from inside the folder:

- **CLI**: `cd ~/vibe-school/vibe-todo && vibe`, then choose **Trust folder**.
- **VS Code**: **File › Open Folder** on `vibe-todo`, then start a new Vibe conversation.
- **Desktop**: in the **Code** tab, click **New Session** and pick the `vibe-todo` folder as a local project.


## Where the files live

| File | Scope | Notes |
|---|---|---|
| `~/.vibe/config.toml` | Every session on your machine | Created the first time you save a setting. Until then, Vibe uses built-in defaults. |
| `.vibe/config.toml` | One project | The closest one walking up from your working directory. Loads only in a [trusted folder](/glossary#trusted-folder). |

Project settings override the same user settings; anything the project file doesn't set comes from your user file.

To keep Vibe's files somewhere else, set `VIBE_HOME`:

```bash
export VIBE_HOME="/path/to/custom/vibe/home"
```

On Windows PowerShell, use `$env:VIBE_HOME = "C:\path\to\vibe-home"` for the current window, or `setx VIBE_HOME "C:\path\to\vibe-home"` to keep it for new terminals.

That moves `config.toml` along with `.env`, `agents/`, `prompts/`, `skills/`, `plugins/`, and `logs/`.

## Change a setting

<SurfaceTabs>
<SurfaceTab surface="cli">

Run `/config` to open the settings browser. Each setting shows its value and where it's set; type to filter, and press Enter to edit. Changes save to `~/.vibe/config.toml` by default. Use **Save to** in the editor to save to the project file or to the current session only.

A few settings have their own shortcuts: `/theme` picks the theme, `/model` the model, and `/thinking` the thinking level.

Prefer a text editor? Open the file directly, then run `/reload` to apply your changes without restarting:

```bash
open ~/.vibe/config.toml        # macOS
xdg-open ~/.vibe/config.toml    # Linux
```

On Windows PowerShell: `notepad "$HOME\.vibe\config.toml"`.

</SurfaceTab>
<SurfaceTab surface="vscode">

The extension doesn't have its own settings panel yet. It runs the bundled Vibe agent with the same configuration as the CLI, so edit `~/.vibe/config.toml` (or ask Vibe to do it), then type `/reload` in the Vibe panel or start a new conversation. See [Extension settings](https://docs.mistral.ai/vibe/code/vs-code-extension/settings).

</SurfaceTab>

The `config.toml` settings in this lesson are documented for the CLI and the VS Code extension. Local sessions in Vibe Desktop share the CLI's core engine and session logs, but their tools and prompts can differ, so don't assume every key applies there. ## A few useful keys

```toml
theme = "mistral-dark"          # "auto" (default), "mistral-dark", "mistral-light", and more
default_agent = "accept-edits"  # the agent new sessions start in
enable_notifications = true     # bell and title update when Vibe needs you
autocopy_to_clipboard = true    # copy text when you release a mouse selection
vim_keybindings = false         # vim Normal and Insert modes in the prompt
enable_telemetry = true         # anonymous usage and error telemetry
```

Every key is listed in the [configuration reference](https://docs.mistral.ai/vibe/code/cli/configuration-reference). Models get their own lesson in [Models](/lessons/models), and tool permissions in [Permissions](/lessons/permissions).

## Who wins

When the same setting is defined in several places, Vibe applies them from highest to lowest priority:

1. **Admin config** from your Organization or Workspace (read-only in `/config`)
2. **The active agent's settings**
3. **Command-line flags** and session-only changes from `/config`
4. **`VIBE_<KEY>` environment variables**, for example `VIBE_ACTIVE_MODEL`
5. **Project** `.vibe/config.toml`
6. **User** `~/.vibe/config.toml`

Any setting can be overridden for one run with its `VIBE_` variable:

```bash
VIBE_THEME=mistral-light vibe
```

On Windows PowerShell, set the variable first, then start Vibe: `$env:VIBE_THEME = "mistral-light"; vibe`. It stays set until you close that window.

## Check your config

- At startup, Vibe warns about settings it doesn't use, such as a misspelled key, and suggests the right name.
- Set `strict_config = true` (or `VIBE_STRICT_CONFIG=1`) to make Vibe refuse to start instead, for example in CI.
- `vibe config schema` prints a JSON schema of every setting, so your editor can validate `config.toml`.

If Vibe won't start after an edit, move the file aside and start again with defaults:

```bash
mv ~/.vibe/config.toml ~/.vibe/config.toml.bkp
vibe
```

On Windows PowerShell: `Rename-Item "$HOME\.vibe\config.toml" config.toml.bkp`, then run `vibe`.

<div class="callout">
API keys don't belong in <code>config.toml</code>. They live in your OS keyring or in <code>~/.vibe/.env</code>, which holds credentials only.
</div>

Learn more in the [configuration documentation](https://docs.mistral.ai/vibe/code/cli/configuration).
