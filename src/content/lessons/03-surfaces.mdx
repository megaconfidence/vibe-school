Vibe is one agent with many front doors. You can reach it from a terminal, from your editor, from a desktop app, or from a browser, and each surface suits a different kind of task. This lesson helps you pick the right one, and explains what carries over when you switch.

## Work or Code

Vibe has two modes ([docs](https://docs.mistral.ai/vibe/choose-chat-work-code)):

- **Work** is for tasks that live across apps, documents, and business tools. It runs in the Vibe web and mobile apps and in Vibe Desktop, uses [connectors](/glossary#connector) like Gmail, Slack, Notion, Linear, and GitHub, and lets you switch between quick answers and deeper, multi-step work with a **fast/think toggle**, or a reasoning level in the model menu, depending on your account.
- **Code** is for tasks that depend on a codebase, a terminal, or an IDE. It reads files, edits code, runs commands, and opens pull requests.

Some typical prompts:

| Work | Code |
|---|---|
| Summarize this 80-page contract and flag the renewal risks. | Explain how authentication works in this repo. |
| Draft replies to my unread emails from the legal team. | Add unit tests for the `parseInvoice` function. |
| Research the top 5 competitors in our space and create a one-page brief. | Run the test suite, fix what fails, and open a PR. |

## The four Code surfaces

- **CLI**: runs in any terminal, with full access to your shell and working tree. It's the most flexible surface and the only one with a non-interactive mode (`vibe --prompt`) for scripts and CI.
- **VS Code extension**: Vibe in a side panel. It adds **editor context**: the active file, your selection, diffs, and source control. No separate CLI install needed.
- **Vibe Desktop**: one app for macOS and Windows that runs **local sessions** on your checkout and **cloud sessions** in a sandbox, with a built-in browser, terminal, file viewer, and pull request panel. Work lives in the same app. Linux support is coming soon.
- **Vibe Code Web**: cloud sessions in a managed sandbox, working directly against GitHub or GitLab repositories. Good for long tasks that end in a branch or pull request, with no local setup.

| | CLI | VS Code extension | Vibe Code Web | Vibe Desktop |
|---|---|---|---|---|
| Local install | Required | Required | None | Required (the app) |
| Repository access | Local clone | Local clone | Directly via GitHub or GitLab | Local clone (local sessions), via GitHub (cloud sessions) |
| Filesystem and shell | Local working tree | Local working tree, through ACP | Remote sandbox | Local (local sessions), remote sandbox (cloud sessions) |
| Custom agents, skills, MCP servers, connectors | Yes | Yes | Yes | Yes |
| Non-interactive mode | Yes (`vibe --prompt`) | No | No | No |
| Best fit | Terminal-first work, automation, CI | Editor-native work and visual review | Remote repository tasks without local setup | Cloud and local sessions in one app |

Full comparison: [Choose CLI, VS Code, web, or Desktop sessions](https://docs.mistral.ai/vibe/code/choose-cli-vscode-web-sessions).

## What's shared between surfaces

- **CLI and VS Code extension** share the same configuration and sessions in `~/.vibe/`: agents, skills, MCP servers, profiles, and conversation history. Start a session in the terminal and resume it in VS Code, or the other way around.
- **Desktop local sessions** share the CLI's core engine and session logs, but Desktop doesn't embed the CLI. Tools and prompts can differ.
- **Code Web and Desktop cloud sessions** run in a managed cloud sandbox, not on your machine.

To see one task travel through every surface, do the [Work across surfaces](/exercises/work-across-surfaces) exercise after the lessons.

## Other IDEs

Vibe implements the [Agent Client Protocol](/glossary#acp) (ACP) and is listed in the ACP registry, so it also runs in ACP-compatible clients, with the same configuration and credentials:

- **JetBrains IDEs** (2025.3.2 or later, with the AI Assistant plugin): open `Settings`, go to `Tools > AI Assistant > Agents`, search for `Mistral Vibe`, and click `Install`. Then pick `Mistral Vibe` in the `AI Chat` agent selector.
- **Clients without a registry**, such as Zed: install the CLI and point the client at the `vibe-acp` command, for example under `agent_servers` in Zed's settings.

Don't use the old Mistral Code Enterprise JetBrains plugin: it's deprecated. See [Use Vibe in other IDEs](https://docs.mistral.ai/vibe/code/use-vibe-in-other-ides).
