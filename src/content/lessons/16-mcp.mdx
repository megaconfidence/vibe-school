Vibe ships with tools for files and the shell. [MCP](/glossary#mcp) servers add more: an issue tracker, a database, a browser, your company's internal API. You add a server once, and its tools appear in every session next to the built-in ones.

The [Model Context Protocol](https://modelcontextprotocol.io) is an open standard, so the same server works with Vibe and with other agents that speak MCP.

## In your project

This lesson gives `vibe-todo` its first MCP server, in the project config so everyone who trusts the repo gets it:

```text
vibe-todo/
└── .vibe/
    └── config.toml    # adds an [[mcp_servers]] entry: fetch_server (uvx mcp-server-fetch)
```

Then you'll use it to read the Python `argparse` docs and ask how the todo CLI could use them.


## Transports

| Transport | Use it when |
|---|---|
| `stdio` | The server is a local process Vibe starts from a command. |
| `http` | The server is reachable over standard HTTP. |
| `streamable-http` | The server is reachable over HTTP and supports streaming responses. |

## Add a server from the command line

`vibe mcp add` writes the server to your user `~/.vibe/config.toml` without starting a session.

A remote server that uses **OAuth** only needs a name and a URL. Vibe opens your browser to sign in:

```bash
vibe mcp add linear --url https://mcp.linear.app/mcp
```

Pass `--no-login` to save it without signing in, and `--scope` (repeatable) to request specific scopes.

A remote server that uses an **API key** reads it from an environment variable:

```bash
vibe mcp add mistralai \
  --url https://api.mistral.ai/mcp \
  --api-key-env MISTRAL_API_KEY
```

You can pass static headers with `--header NAME=VALUE` instead, but they're stored in plaintext, so keep secrets in `--api-key-env`.

A **local** server uses the `stdio` transport. Repeat `--arg` for each argument and `--env NAME=VALUE` for each environment variable:

```bash
vibe mcp add fetch_server --transport stdio --command uvx --arg mcp-server-fetch
```

Remove a server with `vibe mcp remove <name>`. For an OAuth server, that also deletes its stored tokens. Run `vibe mcp add --help` for every option, including `--startup-timeout-sec` and `--tool-timeout-sec`.

`vibe mcp add` only writes to your user config. For a server the whole project should get, or if you use VS Code or Desktop without the CLI on your `PATH`, write it in `config.toml` by hand, as shown next.

## Or write it in config.toml

Each server is a `[[mcp_servers]]` table. It works in `~/.vibe/config.toml` and in a project's `.vibe/config.toml` (loaded only in a [trusted folder](/glossary#trusted-folder)). Servers from both files are combined; when both define the same `name`, the project one wins. Keep top-level keys such as `default_agent` above the first table. For `vibe-todo`:

```toml
# vibe-todo/.vibe/config.toml (after the keys you already have)
[[mcp_servers]]
name = "fetch_server"
transport = "stdio"
command = "uvx"
args = ["mcp-server-fetch"]
```

A stdio server can also take `env = { "LOG_LEVEL" = "info" }`. A remote server with OAuth looks like this:

```toml
[[mcp_servers]]
name = "linear"
transport = "streamable-http"
url = "https://mcp.linear.app/mcp"

[mcp_servers.auth]
type = "oauth"
scopes = []
```

`startup_timeout_sec` (default `10`) and `tool_timeout_sec` (default `60`) are optional on any server. For static auth, use `type = "static"` with `api_key_env` or `headers`. See the [configuration reference](https://docs.mistral.ai/vibe/code/cli/configuration-reference#mcp-servers) for every field.

## Sign in and browse

OAuth works with `http` and `streamable-http` servers. Vibe stores the tokens in your OS keyring, never in `config.toml`.

| Command | What it does |
|---|---|
| `/mcp` | Browse MCP servers and connectors (alias `/connectors`). |
| `/mcp <name>` | List a server's tools. |
| `/mcp add <url>` | Add an OAuth server and sign in. Accepts `--name`, `--scope`, `--transport`, `--no-login`. |
| `/mcp status` | Show each server's status. |
| `/mcp login <name>` | Sign in to an OAuth server. |
| `/mcp logout <name>` | Sign out and delete its tokens. |

## Tool names and permissions

Vibe prefixes every MCP tool with its server's `name`, so keep names short. Set permissions per tool, exactly like the built-in tools from the [Permissions](/lessons/permissions) lesson:

```toml
[tools.fetch_server_get]
permission = "always"

[tools.my_http_server_query]
permission = "ask"
```

Or switch whole servers on and off with patterns (exact names, globs, or regex with `re:`):

```toml
disabled_tools = ["fetch_server_*"]
```

Every MCP tool adds a definition to the context window. Disable the ones you don't use, and check the cost with `/context`.

## Connectors vs. MCP servers

[Connectors](/glossary#connector) are Mistral-managed integrations, the same ones Vibe Work uses (see the [Connectors](/lessons/connectors) lesson). They show up in the same `/mcp` list.

| | Connectors | MCP servers |
|---|---|---|
| **Configured by** | Mistral | You, with `vibe mcp add` or `config.toml` |
| **Auth** | Account or service login | OAuth, headers, environment variables, or API keys |
| **Best for** | Common services | Custom tools, private servers, experiments |

In `/connectors`, press `Enter` to connect or list tools, `e` / `d` to enable or disable, and `r` to refresh. Set `enable_connectors = false` to turn connectors off entirely.

Learn more in the [MCP servers](https://docs.mistral.ai/vibe/code/cli/mcp-servers) and [connectors](https://docs.mistral.ai/vibe/code/cli/connectors) documentation.
