Your `vibe-todo` project now has [skills](/lessons/skills), [agents](/lessons/agents), an [MCP server](/lessons/mcp) and a [hook](/lessons/hooks). A [plugin](/glossary#plugin) packs pieces like these into one folder that you can hand to a teammate or commit to a repo. Installing it adds its pieces to every session without touching anyone's own `config.toml`.

<div class="callout">
Plugin support is <strong>experimental</strong>. The format and features can change, and an update can break existing plugins.
</div>

## In your project

This lesson packages the `code-review` skill as a project plugin in `vibe-todo`, so it can travel to other repositories as one folder:

```text
vibe-todo/
└── .vibe/
    ├── skills/code-review/SKILL.md      # stays: the reviewer subagent uses it
    └── plugins/
        └── todo-review/
            ├── plugin.json              # new: the manifest
            └── skills/
                └── code-review/SKILL.md # new: a copy, run as /todo-review:code-review
```


## Where plugins live

Each subdirectory of a plugins folder is one plugin:

| Scope | Location | Loaded |
|---|---|---|
| Project | `./.vibe/plugins/<plugin>/` | Only in a [trusted folder](/glossary#trusted-folder) |
| User | `~/.vibe/plugins/<plugin>/` | Always |
| Built-in | Shipped with Vibe | Always |

When two plugins share a name, project beats user, which beats built-in. Vibe's built-in `vibe` plugin provides skills such as `/vibe:skill-creator`, `/vibe:worktree`, and `/vibe:import`, which brings your setup over from Claude Code, Codex, or OpenCode. In Vibe 3.1.3 it also includes `/vibe:create-plugin`, which scaffolds a new plugin for you.

## Layout

Only `plugin.json` is required:

```text
release-tools/
├── plugin.json            # Manifest (required)
├── mcp.json               # MCP servers
├── libraries.json         # Python and Node libraries (Vibe extension)
├── connectors.json        # Required connectors (Vibe extension)
├── skills/
│   └── changelog/
│       └── SKILL.md
└── ai.mistral.vibe/       # Vibe-only components (Vibe extension)
    ├── hooks.toml
    ├── knowledge/
    └── agents/
```

## The manifest

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "release-tools",
  "version": "1.0.0",
  "description": "Skills for cutting releases.",
  "extensions": {
    "ai.mistral.vibe": {
      "schemaVersion": 1,
      "displayName": "Release tools"
    }
  }
}
```

- `$schema` must be exactly the 1.0.0 URL. Vibe rejects other versions.
- `name` is 1 to 64 characters: lowercase letters, digits, `.` and `-`. It starts and ends with a letter or digit, with no `--` or `..`.
- `description` is shown in `/plugins` and listed in the agent's context, so say what the plugin is for.
- The `ai.mistral.vibe` extension is optional. **Without it, Vibe loads only `skills/` and `mcp.json`.** Add it to ship hooks, knowledge, subagents, libraries, or connectors.

## What a plugin can ship

| Component | Where | Exposed as |
|---|---|---|
| Skills | `skills/<skill>/SKILL.md` | `<plugin>:<skill>`, run with `/<plugin>:<skill>` |
| MCP servers | `mcp.json` (with its own 1.0.0 `$schema` and `mcpServers`) | Listed in `/mcp`, tagged with the plugin |
| Hooks | `ai.mistral.vibe/hooks.toml` | Prefixed, like `release-tools:audit-bash` |
| Knowledge | `ai.mistral.vibe/knowledge/<name>/KNOWLEDGE.md` | A read-only folder the agent reads when relevant |
| Subagents | `ai.mistral.vibe/agents/<name>.toml` | `<plugin>:<name>` |
| Libraries | `libraries.json` | Added to `PYTHONPATH` and `NODE_PATH` |
| Connectors | `connectors.json` | Checked against your account, not connected |

Every path must stay inside the plugin folder. The [plugins documentation](https://docs.mistral.ai/vibe/code/cli/plugins#components) lists the fields for each component.

## Manage plugins

<SurfaceTabs>
<SurfaceTab surface="cli">

| Command | What it does |
|---|---|
| `/plugins` | Browse this session's plugins: version, scope, components. Anything that failed shows under **Not loaded** with the reason. Press `r` to reload. |
| `/reload-plugins` | Re-read the plugin folders and report what was added (`+`), removed (`-`), or updated (`~`). |

`/reload` doesn't reload plugins. A session **pins** each plugin's content when it starts, so editing a plugin on disk changes nothing until you run `/reload-plugins` or start a new session.

</SurfaceTab>
<SurfaceTab surface="vscode">

The extension reads the same `~/.vibe/plugins/` and project `.vibe/plugins/` folders. Its slash commands don't include `/plugins`, so use the CLI to check what loaded.

After you install or change any plugin, run **Developer: Reload Window** from the Command Palette (or restart VS Code). A new conversation or `/reload` isn't enough: the extension keeps its agent running in the background, and only a window reload makes it read the plugin folders again. Then type `/` and look for the plugin's skills.

</SurfaceTab>
<SurfaceTab surface="desktop">

Desktop local sessions share the CLI's core engine and session logs. Use the CLI's `/plugins` to check that a plugin loads, then start a new Desktop session.

</SurfaceTab>
</SurfaceTabs>

To turn a plugin off without deleting it, list it in `config.toml`:

```toml
disabled_plugins = ["release-tools"]
```

A plugin that sets `"defaultEnabled": false` stays off until you add it to `enabled_plugins`. The built-in `vibe` plugin can't be turned off.

<div class="callout">
On a primary agent, <code>enabled_skills</code> and <code>disabled_skills</code> don't filter plugin skills: <code>disabled_plugins</code> and <code>enabled_plugins</code> do. So <code>/todo-review:code-review</code> works inside <code>builder</code> even though the builder sets <code>enabled_skills = ["new-command", "code-review"]</code>. Subagents are stricter: a subagent's skill lists filter plugin skills by their full <code>&lt;plugin&gt;:&lt;skill&gt;</code> name, so the <code>reviewer</code> subagent only sees <code>todo-review:code-review</code> if you add <code>"todo-review:*"</code> to its <code>enabled_skills</code>.
</div>

## Plugins for other agents

Vibe also loads plugins written for other coding agents, but only their **skills and MCP servers**:

| Format | Marker |
|---|---|
| Claude Code | `.claude-plugin/plugin.json` |
| Codex | `.codex-plugin/plugin.json` |
| Kimi Code | `kimi.plugin.json` or `.kimi-plugin/plugin.json` |
| OpenCode | `.opencode/` content or `opencode.json` |

Hooks in Claude Code or Kimi plugins don't run. Write new plugins in the Agent Plugins 1.0 format.

<div class="callout">
A plugin can start local MCP servers and add tools and instructions to your sessions. <strong>Review it like code before you install it.</strong> Plugins don't change approvals: their tools go through the same <a href="/lessons/permissions">permissions</a> as any other tool.
</div>

Learn more in the [plugins documentation](https://docs.mistral.ai/vibe/code/cli/plugins).
