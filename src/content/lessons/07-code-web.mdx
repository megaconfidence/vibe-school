Vibe Code Web runs the Vibe agent in a cloud sandbox instead of on your machine. You point it at a GitHub or GitLab repository (this lesson uses GitHub), describe the task, and it clones the code, makes the change, runs commands, and opens a pull request for you to review. Close your laptop, and it keeps going. It's the same engine as the CLI, reached from any browser.

## When to use it

Code Web fits tasks that:

- run without your local files, services, or secrets,
- take long enough that you don't want to keep your machine open,
- should end in a branch or pull request.

If the task needs local files, local secrets, or direct access to your machine, use the [CLI](/lessons/cli), [VS Code](/lessons/vscode), or a local session in [Desktop](/lessons/desktop).

## Connect GitHub

The first time you create a project, you install the **Mistral GitHub App**:

1. Choose the GitHub account or organization where the repository lives.
2. Select **all repositories** or **only the repositories** the App should access. Pick the narrowest option that works.
3. Confirm the installation, then authorize the App on your user account.

Organization owners may need to approve the install first. You can change or revoke access any time at [github.com/settings/installations](https://github.com/settings/installations).

Git work uses **your** user access token, so commits and pull requests are authored by you. The agent can clone, branch, commit, push, and open pull requests on authorized repositories. It can't bypass branch protections, required reviews, `CODEOWNERS`, or required status checks.

## Projects

A **project** groups one or more repositories from the **same GitHub owner**, plus the sessions you run against them. To work across owners, create separate projects.

1. Switch to the **Code** tab at the top of the sidebar, then click **New Project** next to **Projects**.
2. In **Create a project**, pick **Using GitHub** (GitLab and a blank project are also offered).
3. Select your GitHub account or organization and click **Next**. Organizations that require SSO are listed separately with a **Reconnect GitHub** button.
4. Search for the repository, select it, and click **Next**. A new repository can take a few seconds to appear.
5. Check the **Project name**, optionally add **Project instructions**, and click **Create project**.

The new project is selected in the prompt box ("…in **your-project**"), so you can type your first task right away. Labels can shift as the app evolves. If yours differ, follow what you see on screen.

Open **View project details** to rename the project, add or detach repositories (changes apply to new sessions), or delete it from the **Danger zone**. Deleting a project or session removes Vibe's history only; your branches and pull requests stay in GitHub.

## Sessions

Type a prompt in the project view, or click **New Session** next to the project in the sidebar. Be specific: name the file, failing test, stack trace, or expected behavior. Vibe names the session after your task (for example *README typos PR*), and the sidebar shows the pull request status next to it, such as **#1: Draft · 1 pull request**.

| Phase | What happens |
|---|---|
| Start | Vibe creates an isolated sandbox |
| Clone | The repository and branch are cloned into it |
| Run | The agent reads, plans, edits, runs commands, and asks questions |
| Review | You inspect the branch or pull request in GitHub |
| End | The sandbox is deleted when the session stops, times out, or errors |

The session view shows an **activity stream** (every command and its output), the files changed, the branch, a link to the pull request, and a prompt box. A live session is **Active**, **Waiting for input**, **Idle**, or **Stopped**. It ends as **Completed**, **Timed out**, or **Error**.

Vibe typically opens the pull request as a **draft** on a `vibe/…` branch, authored by you. Mark it ready for review in GitHub when you're happy with it.

A pull request doesn't end the session. While the sandbox is alive, send follow-ups: paste a reviewer comment or a failing CI log and ask Vibe to fix it. It reuses the same sandbox and branch.

<div class="callout">
Once the sandbox is deprovisioned, a session <strong>can't be resumed</strong>. You can still reopen it to read its history; start a new session to continue the work.
</div>

## Sandbox and limits

Each session gets its own single-tenant sandbox: a default Linux image maintained by Mistral, with a shell, Git, common language runtimes, and CLI utilities. If your project needs something else, the agent installs it during the session. Outbound internet is available (managed by Mistral); nothing can reach the sandbox from outside, and it can't see your machine. Only what's pushed to GitHub survives.

| Limit | Value |
|---|---|
| Maximum session duration | 24 hours |
| Inactivity timeout while waiting for your reply | 3 hours |
| Concurrent sessions per user | Plan-dependent |
| Sessions per day, free users | 2, where access is enabled |
| Sessions per day, paid users | 100 |

Sessions are personal; share the pull request to collaborate. Check [Limits and lifecycle](https://docs.mistral.ai/vibe/code/web/limits-and-lifecycle) for the current values.

## Security

Anything the agent reads (repository files, command output, web pages, comments you paste) can try to redirect it. This is [prompt injection](/glossary#prompt-injection). To stay safe:

- Watch the activity stream as the session runs.
- Keep prompts focused, so off-task actions stand out.
- Treat the sandbox like a CI job: never give it production secrets.
- Review the code in GitHub and rely on branch protections before merging.

## Start from Slack

Teams can also start a session from a Slack thread by mentioning `@Vibe`. The app reads the thread, picks the project and repository (or asks), and posts a link to the web session. An organization admin connects Slack first. This is in progressive rollout. See [Vibe Code Web for Slack](https://docs.mistral.ai/vibe/code/web/slack-integration).

Learn more in the [Vibe Code Web docs](https://docs.mistral.ai/vibe/code/web/get-started).
