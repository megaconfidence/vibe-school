Every time Vibe starts a session, it looks for files called `AGENTS.md` and reads them as standing orders: your preferences, rules, and context that apply to everything it does. You write them once, and every session follows them.

## In your project

This lesson gives `vibe-todo` two instruction files, one for the whole project and one only for the tests:

```text
vibe-todo/
├── AGENTS.md          # new: what the project is, its rules, how to run the tests
└── tests/
    └── AGENTS.md      # new: test rules, loaded when Vibe reads a file in tests/
```


## User vs. project

Vibe reads two kinds of `AGENTS.md`:

- **User** (`~/.vibe/AGENTS.md`): applies to every session on your machine, in every project. Your personal preferences live here. It isn't committed to Git.
- **Project** (`AGENTS.md` in a project): applies when you work in that project. You typically commit it so your whole team, and their agents, get the same instructions.

For a project, Vibe loads every `AGENTS.md` from your working directory up to the root of the [trusted folder](/glossary#trusted-folder). When two files disagree, **the one closest to your working directory wins**:

```text
/
  dir_1/
    AGENTS.md      <- never loaded: not trusted
    dir_2/         <- trusted folder
      AGENTS.md    <- loaded
      dir_3/
        AGENTS.md  <- loaded, wins over dir_2/AGENTS.md
        project/   <- working directory
```

Vibe also picks up `AGENTS.md` files in **subfolders** lazily: the first time it reads a file in `tests/`, it also reads `tests/AGENTS.md`. Folder-specific rules then cost nothing until they're needed.

<div class="callout">
Project <code>AGENTS.md</code> files only load in a <strong>trusted folder</strong>. If Vibe ignores your project rules, check that you trusted the folder (see the <a href="/lessons/permissions">Permissions</a> lesson).
</div>

## What to put in it

Short, specific, actionable rules. Every line is read in every session, so skip anything vague. Here is the kind of file you'll write for `vibe-todo`:

```markdown
# vibe-todo

A tiny command line todo list in Python.

- `todo/cli.py`: argparse parser and one `cmd_<name>()` per subcommand
- `todo/store.py`: `load()` and `save()`, the only module that does file I/O
- `tests/`: unittest suite (has its own AGENTS.md)

## Rules

- Python 3.10+, standard library only. Never add a dependency.
- Every subcommand is a `cmd_<name>(args) -> int` function registered in `build_parser()`.
- Return `0` on success and `1` when a task id doesn't exist.

## Commands

- Run the tests: `python3 -m unittest`
```

On Windows, the Python command is often `python` rather than `python3`; write the one that works on your machine.

And `tests/AGENTS.md` holds the rules that only matter for tests: use `unittest`, call the CLI through the `run_cli` helper, never touch the real `.todo.json`, and add an unknown-id test for commands that take a task id.

Your personal `~/.vibe/AGENTS.md` is for preferences that follow you everywhere, such as "Be concise" or "Use Conventional Commits".

## Create a project AGENTS.md

Vibe has no `/init` command. Just ask:

```
Scan this project and write an AGENTS.md that describes its structure, how to run the tests, and the conventions you see.
```

Review what it writes, trim it, and commit it. In `vibe-todo` you'll do exactly this, then tighten the draft with the rules above.

## Apply your changes

<SurfaceTabs>
<SurfaceTab surface="cli">

Run `/reload` to reload configuration, agent instructions, and skills without restarting. Run `/context` to see how much of the context window the system prompt (including your `AGENTS.md` files) uses.

</SurfaceTab>
<SurfaceTab surface="vscode">

The extension shares the CLI's configuration, so it uses the same `~/.vibe/AGENTS.md`. Type `/reload` in the Vibe panel, or start a new conversation with `Mod+N`.

</SurfaceTab>
<SurfaceTab surface="desktop">

Local sessions in Vibe Desktop share the CLI's core engine, but their prompts can differ, so check that your rules are followed. Start a new session to pick up changes.

</SurfaceTab>
