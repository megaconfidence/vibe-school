Some tasks don't need your laptop at all. In this exercise, you'll hand a bug to a [Vibe Code Web](/glossary#code-web) session. It runs in a cloud [sandbox](/glossary#sandbox), fixes the bug on a branch, and opens a pull request. You review it in GitHub and ask for changes, like you would with a teammate.

## What you'll need

- A GitHub repository you can push to, with a small, real bug in it. A failing test is ideal. A throwaway repo with a bug you planted works too.
- A Mistral account with access to Vibe Code.
- Optional: the [GitHub CLI](https://cli.github.com) (`gh`), so your local Vibe session can inspect the pull request with you.

## Start the session

<SurfaceTabs>
<SurfaceTab surface="code-web">

1. Open Vibe Code Web from the **Code** tab in Vibe.
2. Create a project: click **New Project** next to **Projects** and pick **Using GitHub**. Choose your account, search for the repository, select it, and click **Next**. Check the **Project name**, optionally add **Project instructions**, then click **Create project**. The first time, you're asked to install the Mistral GitHub App.
3. Click **New session** and enter your prompt.

</SurfaceTab>
<SurfaceTab surface="desktop">

Switch to **Code** and start a **cloud session** against a repository connected to a project. Cloud sessions in Desktop use the same projects, sessions, and sandbox as Vibe Code Web.

</SurfaceTab>
</SurfaceTabs>

A good prompt names the file, the failing test or stack trace, and what "fixed" means:

```text
The test test_parse_date in tests/test_dates.py fails with the error below.
Find the cause, make the smallest fix, run the tests, and open a pull request.
Don't weaken the test.
```

## Review and iterate

The session view shows an activity stream of every command and its output, the files changed, the branch, and a link to the pull request. Detailed review happens in GitHub, where your branch protections, required reviews, and checks apply.

A pull request doesn't end the session. While it's still active, send follow-ups in the same session: paste a reviewer comment or a failing CI log and ask the agent to address it. It reuses the same sandbox and branch.

<div class="callout">
Once the sandbox is deprovisioned, a session <strong>can't be resumed</strong>. To continue, start a new session. See <a href="https://docs.mistral.ai/vibe/code/web/limits-and-lifecycle">Limits and lifecycle</a>.
</div>

## Tips

- **Start small.** A well-scoped task with a clear test teaches you more than a vague "clean up the code".
- **Grant narrow access.** Install the GitHub App on selected repositories only.
- **Everything must be in the repo.** The sandbox can't reach your machine, local files, or local secrets. If the task needs those, use a [local session](/lessons/desktop) instead.
- **Treat repo content as untrusted input.** Read the [Security](https://docs.mistral.ai/vibe/code/web/security) page on prompt injection.
