One agent is useful. Two working at the same time, on different tasks, without stepping on each other, is faster. In this exercise, you'll run two Vibe sessions in parallel on the same repository, each in its own [worktree](/glossary#worktree), then merge their work.

## Why worktrees

Two conversations in the same checkout share the same files. If both edit `README.md`, they overwrite each other. A **git worktree** is a second checkout of the same repository on its own branch. Each agent gets its own folder, and git history stays shared, so merging is ordinary git.

<div class="callout">
Worktrees isolate files, not everything. Dependencies, environment variables, and server ports may still need separate setup. Two development servers can't both use the same port just because they run in different worktrees.
</div>

## Start two sessions

<SurfaceTabs>
<SurfaceTab surface="cli">

Open two terminals in your repository and start one session in each:

```bash
# terminal 1
vibe --worktree task-a

# terminal 2
vibe --worktree task-b
```

Vibe creates each worktree under `~/.vibe/worktrees/` on a branch with that name, or reuses it if it already exists. `--worktree` trusts the worktree for that run. To let Vibe pick the name from your prompt, put the prompt first:

```bash
vibe "Add tests for the parser" --worktree
```

When an interactive session ends, Vibe removes a worktree it created if it holds no changes, and asks you otherwise.

</SurfaceTab>
<SurfaceTab surface="desktop">

In the **Code** tab, click **New Session**, pick the repository, and select **Worktree** in the selector under the input (next to **Local** and **Cloud**). Give it one task. Then start a second **Worktree** session for the other task.

In a **Local** session, you can also ask for a worktree before any edit:

```text
Use a new Git worktree for this task. Add tests for the parser,
leaving my current checkout unchanged.
```

Or let one main session coordinate the work through **sub-sessions**:

```text
Create a sub-session to add tests for the parser and another to update
the README. Use separate worktrees for each. Keep coordinating here and
tell me when both are ready.
```

Sub-sessions appear nested under the main session in the sidebar. Each has its own files, terminal, and **+ → Git Changes** panel, so select the right conversation before you inspect anything.

</SurfaceTab>
</SurfaceTabs>

## Bring it together

Review each branch on its own, run its tests, and commit. Then merge both into your main branch (or open two pull requests). If they conflict, ask Vibe to resolve the conflict, explain what it did, and leave it for you to review.

## Tips

- **Pick independent tasks.** Parallel work pays off when tasks touch different files. Two edits to the same function will conflict.
- **Name worktrees after the task.** `task-a` is fine for practice; `parser-tests` is better in real life.
- **Check what's left.** `git worktree list` shows every worktree of the repository.

More in the [Parallel work](/lessons/parallel) and [Desktop](/lessons/desktop) lessons, and the docs on [CLI worktrees](https://docs.mistral.ai/vibe/code/cli/work-with-cli#worktrees) and [Desktop parallel tasks](https://docs.mistral.ai/vibe/code/desktop/parallel-tasks).
