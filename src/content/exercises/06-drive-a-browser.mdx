Vibe can read files and run commands, but it can't see a web page. An [MCP](/glossary#mcp) server fixes that. In this exercise, you'll add the [Chrome DevTools MCP server](https://github.com/ChromeDevTools/chrome-devtools-mcp) and have Vibe open pages, read them, click through them, and take screenshots.

## Prerequisites

- [Node.js](https://nodejs.org), for `npx`.
- Google Chrome.

## Add the server

The server runs as a local process, so it uses the `stdio` transport:

```bash
vibe mcp add chrome-devtools --transport stdio --command npx --arg=-y --arg chrome-devtools-mcp@latest
```

Each `--arg` is one argument. Write `--arg=-y` with an equals sign: `--arg -y` fails because the parser reads `-y` as a flag of its own. The command writes this to your user config:

```toml
[[mcp_servers]]
name = "chrome-devtools"
transport = "stdio"
command = "npx"
args = ["-y", "chrome-devtools-mcp@latest"]
```

## What to try

Start simple, then pick something you actually want to automate:

- "Open https://docs.mistral.ai/vibe and summarize what's on the page."
- "Open my local site at http://localhost:8000, check the console for errors, and take a screenshot."
- "Fill out the contact form on my test page with sample data and tell me what happens."
- "Compare the pricing sections of these two pages."

The first tool calls ask for approval. Read what each one does before you approve it.

## Tips

- **Tool names get a prefix.** MCP tools appear as `chrome-devtools_<tool>`, so you can set [permissions](/lessons/permissions) per tool in `config.toml`.
- **Allow reads, ask for writes.** Once you trust a read-only tool, set it to `permission = "always"`. Keep clicks and form fills on `ask`.
- **Remove it any time** with `vibe mcp remove chrome-devtools`.

More in the [MCP](/lessons/mcp) lesson and the [MCP servers docs](https://docs.mistral.ai/vibe/code/cli/mcp-servers).
