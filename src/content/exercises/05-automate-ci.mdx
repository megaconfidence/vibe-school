Vibe doesn't need you at the keyboard. In [programmatic mode](/glossary#programmatic-mode) it takes one prompt, does the work, prints the result, and exits, which makes it a good fit for CI. In this exercise, you'll add a GitHub Actions workflow that summarizes every pull request and posts the summary as a comment.

## Try it locally first

```bash
vibe -p "Summarize this project in three bullet points" --max-turns 3 --output text
echo $?
```

`text` prints only the final answer. `json` prints the session messages as a JSON array when the run ends, and `streaming` prints one JSON object per message as it goes. The exit code tells a script how the run ended:

| Exit code | Meaning |
|---|---|
| `0` | The agent finished. |
| `1` | The run couldn't start, for example an invalid flag or config. |
| `2` | The model API or the runtime failed. |
| `3` | The agent stopped before finishing: a limit was reached, the run was stopped, or the model declined. |

## A pull request summary workflow

Add your API key as a repository secret named `MISTRAL_API_KEY`, then create `.github/workflows/vibe-pr-summary.yml`:

```yaml
name: Vibe PR summary

on:
  pull_request:

permissions:
  contents: read
  pull-requests: write

jobs:
  summary:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: astral-sh/setup-uv@fac544c07dec837d0ccb6301d7b5580bf5edae39 # v8.2.0

      - name: Install Vibe
        run: uv tool install mistral-vibe

      - name: Summarize the pull request
        env:
          MISTRAL_API_KEY: ${{ secrets.MISTRAL_API_KEY }}
          BASE_SHA: ${{ github.event.pull_request.base.sha }}
        run: |
          git diff "$BASE_SHA"...HEAD > pr.diff
          vibe \
            -p "Read pr.diff. Write a short Markdown summary of this pull request for reviewers: what changed, why, and any risks. Output only the summary." \
            --enabled-tools read_file \
            --max-turns 5 \
            --max-price 0.50 \
            --output text > summary.md

      - name: Post the summary
        env:
          GH_TOKEN: ${{ github.token }}
        run: gh pr comment ${{ github.event.pull_request.number }} --body-file summary.md
```

A few choices worth noticing:

- **`--enabled-tools read_file`** gives the agent one tool. In programmatic mode, it disables all the others.
- **`--max-turns` and `--max-price`** bound the run. The price limit relies on model prices in your config, so treat it as indicative, not a hard budget.
- **No `--auto-approve`.** Tool calls that need approval are denied and reported on stderr. That's what you want for untrusted input.

Programmatic mode never prompts for trust, so it ignores a project's <code>.vibe/</code> config and <code>AGENTS.md</code> unless you pass <code>--trust</code>. Add it if you want your <a href="/lessons/instructions">project instructions</a> to apply in CI.

## The official action

The `mistral-vibe` repository ships a composite action, [`action.yml`](https://github.com/mistralai/mistral-vibe/blob/main/action.yml). It installs Vibe and runs `vibe -p` with your prompt:

```yaml
- uses: mistralai/mistral-vibe@v3.1.3
  with:
    prompt: "Check the README for broken instructions and list them."
    MISTRAL_API_KEY: ${{ secrets.MISTRAL_API_KEY }}
```

The key is passed as an **input**, not an environment variable. The action runs `vibe -p` with no extra flags and exposes no outputs, so the answer appears in the job log. Use it for quick jobs, and call the CLI directly, as above, when you need budgets, tool limits, or the output as a file.

## Tips

- **Forks don't get secrets.** Pull requests from forks run without `MISTRAL_API_KEY`. Test with a branch in your own repository.
- **Keep an audit trail.** `--output-dir out/` writes `export.json` (version, token usage, cost, stop reason, outcome) and a copy of the session, which you can upload as an artifact.
- **Treat PR content as untrusted.** A diff can contain text written to steer the agent. Keep tools narrow and budgets low.
